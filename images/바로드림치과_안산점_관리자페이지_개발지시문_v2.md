# 2. 시스템 구조

## 2.1 전체 시스템 구조

방문자 사이트 (정적 HTML)
- 방문자가 barodreamdental.kr 접속
- 24개 HTML 페이지 서빙
- 실시간 데이터는 클라이언트 JavaScript로 Supabase API 호출
- SEO 중요 데이터는 이미 HTML에 삽입되어 있음
- Cloudinary에서 이미지 제공

관리자 페이지 (독립 앱)
- 원장 또는 아벨이 admin.barodreamdental.kr 접속
- Supabase Auth로 로그인
- 관리자 UI에서 콘텐츠 추가 편집 삭제
- Cloudinary로 이미지 업로드
- SEO 중요 데이터 변경 시 GitHub Actions 트리거

## 2.2 데이터 흐름 두 가지 패턴

패턴 A 실시간 데이터 (클라이언트 사이드 API)

적용 대상
- 팝업 관리
- 상담 예약 폼
- 이벤트 (진행 중)
- 공지사항 (최신)
- 진료 시간 (임시 변경 반영)

흐름
관리자가 데이터 변경
→ Supabase 데이터베이스 업데이트
→ 방문자가 HTML 페이지 접속
→ 페이지 로드 시 JavaScript가 Supabase API 호출
→ 최신 데이터 즉시 표시
→ 재빌드 불필요

장점
- 즉시 반영
- 재빌드 없음
- 유지보수 간단

단점
- SEO 노출 안 됨 (하지만 이 데이터들은 SEO 중요하지 않음)
- JavaScript 실행 필요

패턴 B SEO 중요 데이터 (빌드 시 삽입)

적용 대상
- 리뷰 (감동 리뷰 5개)
- 전후사진 갤러리
- 원장 프로필
- 진료 정보 (진료 페이지 콘텐츠)
- FAQ
- 갤러리
- 칼럼 목록

흐름
관리자가 데이터 변경
→ Supabase 데이터베이스 업데이트
→ 관리자 페이지가 GitHub Actions 트리거
→ GitHub Actions 워크플로우 실행
→ 스크립트가 Supabase 데이터 조회
→ 해당 HTML 파일의 특정 영역에 데이터 삽입
→ Git 커밋 & 푸시
→ Vercel 자동 재배포
→ 방문자 사이트에 반영 (몇 분 소요)

장점
- SEO 노출됨
- 로딩 속도 빠름
- 방문자 JavaScript 불필요

단점
- 재빌드 필요 (5분 정도)
- GitHub Actions 세팅 필요

## 3.4 Row Level Security 정책

각 테이블에 RLS 정책 적용

```sql
-- 예시 팝업 테이블
ALTER TABLE popups ENABLE ROW LEVEL SECURITY;

-- 방문자 사이트 (익명)는 활성 팝업만 조회
CREATE POLICY "Public can read active popups"
  ON popups
  FOR SELECT
  USING (is_active = true AND end_date >= NOW());

-- 관리자는 모든 작업 가능
CREATE POLICY "Admins can do everything on popups"
  ON popups
  FOR ALL
  USING (
    auth.uid() IN (SELECT id FROM admins WHERE is_active = true)
  );
```

모든 테이블에 유사한 RLS 정책 적용.

# 8. GitHub Actions 워크플로우

## 8.1 워크플로우 개요

목적
- 관리자가 SEO 중요 데이터 변경 시 방문자 HTML 재빌드
- Supabase 데이터를 정적 HTML에 삽입
- Git 커밋 & 푸시

## 8.2 워크플로우 파일

경로 barodream-ansan 저장소의 .github/workflows/rebuild-site.yml

```yaml
name: Rebuild Static Site
on:
  workflow_dispatch:
    inputs:
      trigger_source:
        description: 'Trigger source'
        required: false

jobs:
  rebuild:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install dependencies
        run: npm install @supabase/supabase-js cheerio fs-extra
      
      - name: Fetch data from Supabase
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_SERVICE_KEY: ${{ secrets.SUPABASE_SERVICE_KEY }}
        run: node scripts/inject-data.js
      
      - name: Commit and push changes
        run: |
          git config --local user.email "action@github.com"
          git config --local user.name "GitHub Action"
          git add .
          git diff --quiet && git diff --staged --quiet || (git commit -m "chore: auto-rebuild from admin" && git push)
```

## 8.3 데이터 삽입 스크립트

경로 scripts/inject-data.js

역할
- Supabase에서 최신 데이터 조회
- 각 HTML 파일의 마킹된 영역 찾아 데이터 삽입
- 예 리뷰 전후사진 원장 프로필 진료 정보 FAQ 칼럼

스크립트 예시 골격
```javascript
const { createClient } = require('@supabase/supabase-js');
const cheerio = require('cheerio');
const fs = require('fs-extra');

const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_SERVICE_KEY);

async function injectReviews() {
  const { data: reviews } = await supabase
    .from('reviews')
    .select('*')
    .eq('is_featured', true)
    .eq('is_active', true)
    .order('display_order');
  
  const html = await fs.readFile('index.html', 'utf-8');
  const $ = cheerio.load(html);
  
  const reviewsHtml = reviews.map(r => `
    <div class="review-card">
      <p class="review-content">${r.content}</p>
      <span class="reviewer">${r.patient_name}</span>
    </div>
  `).join('');
  
  $('#reviews-container').html(reviewsHtml);
  
  await fs.writeFile('index.html', $.html());
}

async function injectBeforeAfter() {
  // 전후사진 삽입 로직
}

async function injectDoctors() {
  // 원장 프로필 삽입 로직
}

// 실행
(async () => {
  await injectReviews();
  await injectBeforeAfter();
  await injectDoctors();
  // 기타 삽입 함수들
})();
```

# 13. 클로드 코드에게 최종 요청

## 13.1 작업 시작 전 확인

시작 전 다음 정보 확인
- 방문자 사이트 저장소 위치 확인
- 24개 HTML 페이지 리스트 확인
- 각 페이지의 데이터 삽입 영역 파악
- 이미 있는 SEO 요소 파악

## 13.2 작업 순서

이 지시문을 받은 클로드 코드는 다음 순서로 진행

1단계 개발 환경 확인
- Node.js 버전 확인
- npm 또는 yarn 확인

2단계 Supabase 프로젝트 생성 안내
- 사용자에게 Supabase 계정 생성 요청
- 프로젝트 정보 (URL, anon key) 요청

3단계 데이터베이스 스키마 SQL 실행
- 14개 테이블 스키마 SQL 파일 생성
- 사용자에게 Supabase SQL Editor에서 실행 요청

4단계 관리자 페이지 프로젝트 초기 세팅
- 새 Astro + React 프로젝트 생성
- 필요 패키지 설치
- Tailwind + shadcn/ui 세팅

5단계 인증 시스템 구현
- 로그인 페이지
- 미들웨어
- 세션 관리

6단계 레이아웃 및 공통 컴포넌트

7단계 각 메뉴 순차 개발
- 우선순위 1 (메뉴 1-6)
- 우선순위 2 (메뉴 7-12)
- 우선순위 3 (메뉴 13-14)

8단계 방문자 사이트 연동
- 실시간 API 스크립트 삽입
- 데이터 삽입 영역 마킹
- GitHub Actions 워크플로우 세팅

9단계 배포
- Vercel 배포
- 도메인 연결

10단계 매뉴얼 작성
